## TD-20261026-01：UDP 测试未满足关闭 VPN 的环境前置条件

- 日期：2026-10-26（中断后记录）；状态：环境阻塞 / 原因未确认。
- 影响版本与环境：dev 0fc9e120，Windows 11；仅同机双进程，未涉及个人网盘。
- 关联历史故障：TD-20261025-01；历史 peer 出口验证允许保留 TUN，本次用户明确要求关闭，不能沿用旧验收条件。

### 症状与影响

复核发现 PulseVPN 和 PulseVPNCore 仍运行，启动时间早于本轮测试。
此前虽已确认虚拟接口未连接、临时关闭系统静态代理并清除子进程代理环境变量，仍不满足用户要求的“关闭代理软件及 TUN/VPN”。已有网络结果只保留为局部观测，不是前置条件合格的验收通过。

### 触发条件与复现

测试后列出 VPN 进程发现两进程；两次 Stop-Process 后再枚举仍检测到匹配进程。
第二次已等待原进程退出。没有继续修改服务、驱动或自启动配置。

### 根因与证据

未确认进程为何仍出现；没有证据确认看门狗、服务、自启动或用户动作中的哪一种机制。
防火墙三个 profile 均开启，物理 Wi-Fi 为活跃默认路由，aTrust 虚拟接口未连接；实际公网出口及 CGNAT 未核实。
详细边界和脱敏结果见 [测试交付](validation/udp-2026-10-25/README.zh-CN.md)。

### 解决办法与恢复操作

没有产品修复。停止前置检查失败后的测试，不产生 clean-network 成功结论。
finally 恢复原 ProxyEnable=1 并启动原 VPN 程序；中断后检查 UI/core 存在，无 twodrive 测试进程。
未更改 VPN 个人配置、系统路由、防火墙策略或个人数据。

### 验证结果与边界

环境阻塞保留；本地功能回归不等于关闭代理后的网络验收。
仅一台设备，跨 NAT、真实网络异常、两小时和桌面运行验证仍缺失。

### 防复发措施与后续

下一轮应在关闭软件后重新核对进程、代理/PAC、接口、路由和实际出口，并在测试过程中留证；完成后恢复个人配置。
复现工具不会自行更改全局网络设置。所有报告显式标记跨 NAT 和连续路径证据缺失。

### 交付记录

本分支测试脚本与脱敏报告；提交和 PR 信息由 Git 历史及交付回复给出，尚未合并。

## TD-20261025-01：同机 1 GiB 序列首次操作超时，后续通过但根因未确认

- 日期：2026-10-25；状态：调查中 / 根因未确认。
- 影响版本与环境：dev 0fc9e120 的原生 Windows CI 产物，Python 3.14，同机双 CLI；网络前置限制见 TD-20261026-01。
- 关联历史故障：历史跨网 64 MiB 发送预算不足记录仅作为相邻机制参考；本次同机且预算 600 秒，不能认定同根因。

### 症状与影响

首轮一千小文件及 100 MiB 后，1 GiB 对应操作触发测试工具 TimeoutError。
该轮未假报完成；首版脚本未保存失败操作阶段，因此不能确定 PUT、GET、MOVE 后 GET 中哪一步超时。

### 触发条件与复现

在独立临时状态运行 reliability.py --small-count 1000 --attempts 1 --full --timeout 600。
首轮约 905 秒失败；随后单独大文件序列及原完整序列复测分别约 65 / 180 秒通过。
结果不稳定，尚未形成稳定最小复现。

### 根因与证据

根因未确认；未区分后端、测试工具、系统调度或网络配置影响。
[首轮失败](validation/udp-2026-10-25/local-corpus-first.json)保留，后两次报告分别为 local-large-retry.json 和 local-corpus-retry.json。
后者 1 GiB PUT 23.035 秒、GET 16.208 秒，完整大小与 SHA-256 相同；这不是修复证据。

### 解决办法与恢复操作

未修改生产代码。测试工具增加失败阶段、1 秒 Windows 后端 CPU/工作集采样、响应截断拒绝和整体请求期限。
补充慢响应头/响应体、截断和状态码回归，防止工具假成功或无限等待；没有自动重放写请求。
每轮 finally 停止自有 CLI，删除自有随机集合与临时状态。报告确认首轮共享残留文件数为 0，进程已退出；未逐端口验证泄漏。

### 验证结果与边界

测试工具五项回归通过；最终工具同机 CLI 小文件检查通过。
1005 文件完整序列后续通过，包含 1000 个逐个传输小文件、基本文件及 100 MiB/1 GiB；MOVE 后再次完整校验。
此前通过的报告来自逐步完善中的工具版本，字段不同，原始报告保留；不能当作最终工具逐项重新运行的证据。
真实跨 NAT、长期稳定性、客户端/服务端中途退出恢复与桌面验收未覆盖。

### 防复发措施与后续

将工具五项独立 HTTP 回归加入原生 Linux/Windows workflow；再次发生需保存失败阶段、双方有限诊断与资源样本。
当前 CLI 只输出配对初始路径，需后端连续遥测后才能验收传输全过程的直连/中继结论。
